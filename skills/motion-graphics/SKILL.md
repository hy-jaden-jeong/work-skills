# 모션그래픽

`<스킬 폴더>`는 이 파일이 있는 폴더다. 영상별 자유 HTML/SVG composition을 만들고 이 skill의 exporter로 무음 MP4를 납품한다. 기본 독자는 영어를 이해하고 기술을 어느 정도 아는 사람이며 제목·라벨·질문·결과 문구는 영어로 쓴다. skill 지침과 작업 보고의 언어는 영상 출력 언어와 구분한다.

기본 산출물은 MP4다. GIF는 기본으로 생성하지 않으며, 명시적 요청이 있을 때 완성 MP4를 일회성으로 변환한다. 별도 GIF skill은 만들지 않는다.

## 무엇이 움직이면 이해되는가

주제와 근거에서 시청자가 영상 끝에 답할 핵심 질문 하나를 잡는다. 이미 알려진 독자·사용처·길이는 적용하고 초안까지 만든다. 사용자가 기획 확인을 요청했거나 장면의 사실을 결정할 자료가 비어 있을 때만 먼저 묻는다.

- 기술 원리는 데이터·값·구조의 변화로, 업무 장면은 실제 입력·담당자·처리 결과로, 개념 비교는 같은 사례에서 달라지는 관계와 결과로 보여 준다. 질문에 맞는 사물과 배치를 고르고 고정 장면 유형이나 단계·노드 수에 맞추지 않는다.
- 실행 전에 시각 스토리보드에 대상, 처음과 끝의 값, 변화의 원인, 관찰할 순간을 적는다. composition의 주석과 `keyframes`로 남겨도 된다. 시간별 실행 상태는 장면 코드 한 곳에서 소유한다.
- 장면마다 무엇이 일어나고 왜 중요한지 짧은 영어 설명을 계속 보이게 하고, 장면이 바뀌면 설명도 갱신한다. 이름·값·단위는 대상 곁에서 짚는다. 긴 문단을 읽게 하지 않으며, 설명과 대상의 이동·변형·대응이 함께 원인과 결과를 전달하게 한다. 글자 등장이나 선 점멸만으로 처리를 암시하지 않는다.
- 확대·이동·전환 뒤에도 같은 객체와 관계를 유지해 앞 장면과 대응하게 한다. 현재 핵심 동작 하나에 시선을 모으고, 이동한 값과 그 결과를 같은 ID로 잇는다. 연출 속도를 실제 처리 시간이나 성능 향상으로 제시하지 않는다. 가상 사례는 화면에서 `(fictional)`로 표시한다.

낯선 필수 용어는 그 대상 곁에서 영어로 짧게 풀어 준다. 연출은 담백하게 하고 변화가 작거나 복잡한 곳을 확대한다.

## 화면과 시간

가로:세로 **4:5**, 1080×1350·30fps를 기본으로 한다. 다른 비율은 별도 요청이 있을 때 쓴다. 요청한 내용을 모두 설명하는 데 필요한 장면·움직임·관찰 시간으로 길이를 정하며, 몇 분이 되어도 된다. 고정 초수나 상한에 맞춰 내용을 덜지 않는다. 짧은 이동은 바로 이어 주고 새 관계를 파악해야 하는 순간에 관찰 시간을 둔다. 읽은 상태가 그대로 남는 대기는 줄이고, 전체 배속 대신 이동·관찰·결말 시간을 각각 조정한다.

전체 제목은 도입부에서 짧게 보여 준 뒤 걷는다. 본문에서는 화면 위에 같은 큰 제목을 계속 고정하지 않고, 현재 장면의 짧은 설명이 시선을 안내하게 한다.

레퍼런스가 없으면 어두운 중립 배경과 절제된 강조색, 읽기 쉬운 영문 글꼴을 쓴다. 주요 라벨은 1080px 폭에서 30px 이상으로 시작하고 휴대폰 폭에서도 확인한다. 공간이 부족하면 장면을 나누거나 확대하며, 중요한 요소를 가장자리에서 띄운다. 결말을 잠시 유지하고 반복 재생이 인과를 역전시키지 않게 한다.

패널 여백·열 중심·행 중심을 먼저 정하고 관련 요소가 같은 기준 좌표를 쓰게 한다. 숫자, 카드 속 글자, 화살표는 실제로 그려진 글자의 중심을 기준으로 맞춘다. 서로 다른 글꼴 크기에 같은 baseline을 쓰거나 요소별 좌표를 따로 잡으면 눈에 보이는 정렬이 어긋난다. 확대·이동 중간에도 정렬과 간격이 유지되는지 본다.

영상은 완전 무음이다. 오디오 stream을 넣지 않고 음원을 생성하지 않는다. 움직임과 짧은 설명으로 질문·변화·결과가 이어지게 한다. 외부 이미지·폰트를 쓰면 로컬 원본과 출처·사용 조건을 남긴다.

## 만들고 내보내기

한 영상의 원본은 `composition.json`과 `scene.html`이다. `assets/cache/`, `assets/order-entry/`, `assets/counterparts/`는 기술 원리·업무·비교 예제다. KG 의미 모델과 SQL 값 대응 사례에는 [assets/kg-friends/EXAMPLE.md](assets/kg-friends/EXAMPLE.md)를 읽는다. 현재 질문에 가까운 예제만 읽고, 모양이 맞지 않으면 새 장면을 만든다.

기존 예제는 움직임과 데이터 대응을 참고하는 자료다. 고정 제목·배치·길이를 그대로 복사하지 않고, 현재 규칙에 맞춰 장면 설명·도입 제목·전체 내용에 필요한 길이를 다시 구성한다.

- JSON에는 `version: 1`, `title`, 상대 경로 `scene`, `width`, `height`, `fps`, `duration`, `representativeTime`, `keyframes: [{time, label}]`을 둔다. `audio`는 쓰지 않는다. 값과 실행 조건은 예제 JSON을 참고한다.
- 별도 로컬 파일을 참조하면 선택 항목 `assets: ["상대 경로", …]`에 CSS·이미지·font·script와 그 파일들이 참조하는 필수 자산까지 등록한다. 경로 기준은 composition 폴더이며 자산을 그 안에 둔다. 등록 누락은 exporter 오류로 확인한다. 그래야 납품 원본으로 같은 화면을 재생성할 수 있다.
- HTML의 `#canvas`가 캡처할 전체 화면이다. `window.renderAt(t)`는 절대시간(초)만으로 **전체** DOM 상태를 설정하고 JSON으로 직렬화할 수 있는 의미 상태(ID·값·phase 등)를 반환한다. 순서를 바꿔 호출해도 같은 시간이면 같은 상태여야 한다. timer, 앞 프레임의 누적 상태, 원격 asset에 기대지 않는다.
- 장면은 자유롭게 작성하되 인코딩·파일 검사는 아래 공통 도구를 쓴다. 다른 skill의 script를 import하지 않는다.

```bash
python3 -m venv <스킬 폴더>/.venv
<스킬 폴더>/.venv/bin/python -m pip install -r <스킬 폴더>/requirements.txt
npm install --prefix <스킬 폴더>
<스킬 폴더>/.venv/bin/python <스킬 폴더>/scripts/render_motion.py /path/to/composition.json --check-only
<스킬 폴더>/.venv/bin/python <스킬 폴더>/scripts/render_motion.py /path/to/composition.json --output /path/to/output
```

사용자가 다른 비율을 명시한 경우에만 JSON의 크기를 바꾸고 검사·내보내기 명령에 `--allow-other-aspect`를 붙인다. 일반 제작에서는 플래그 없이 1080×1350·4:5를 유지한다.

의존성이 이미 있는 Python이면 `.venv/bin/python` 대신 그 실행 파일을 써도 된다. Python 3, Node.js, Chrome과 장면에서 선택한 로컬 글꼴이 필요하다. 기본 탐색이 안 되면 `NODE_BINARY`, `NODE_PATH`, `CHROME_PATH`, `MOTION_FONT_PATH`로 위치를 지정한다. ffmpeg는 `FFMPEG_PATH`·PATH·설치한 imageio-ffmpeg에서 찾는다. OS 폰트는 배포 원본에 복사하지 않고 이름과 설치 조건을 남긴다.

MP4(H.264·yuv420p, video stream만 포함), 대표 PNG, 검수 이미지, 편집 원본, 재생성 명령과 검사 기록을 남긴다. 공개 repo에는 가상 예제의 원본만 넣고 생성 영상은 납품 폴더에 둔다.

## 보고 보내기

파일 검사와 이해도 검토를 구분한다. exporter의 decode·video-only stream·크기·길이·fps·시점·시간 순서 검사 결과를 확인한 뒤, 주요 프레임과 전환 중간에서 값·대상·관계·정렬을 직접 본다. 원본 크기와 휴대폰 폭에서 영어 설명·라벨·잘림을 확인하고 전체 영상을 실제 속도로 보며 다음 변화를 불필요하게 기다리는 구간을 찾는다. 정지 분석과 장면 이음매는 검토 후보이며 프레임을 자동 삭제하지 않는다. contact sheet만으로 재생 리듬을 합격 처리하지 않는다. 재생 도구가 없으면 그 한계를 밝히고 정지 프레임 검사와 구분한다.

정지·변화 후보 보고가 필요하면 아래 도구를 선택해 쓴다. `--fps`는 실제 영상의 fps에 맞춘다.

```bash
<스킬 폴더>/.venv/bin/python <스킬 폴더>/scripts/audit_motion.py /path/to/output/frames --fps 30 --output /path/to/output/pace-audit.json
```

문제가 있으면 장면을 고쳐 다시 검사한다. 편집 원본으로 새 process에서 재생성해 누락된 의존성과 asset을 확인한다. 최초 시각 기준 견본은 사용자에게 보여 주고 느낌을 확인한다. 납품에는 파일 링크, 실제 길이·크기, 재생성 명령, 확인한 결과와 남은 제한을 적는다. 자동 검사를 시청자의 이해도 증명으로, 파일 생성을 LinkedIn 업로드·피드 재생 확인으로 표현하지 않는다.
