# 모션그래픽

`<스킬 폴더>`는 이 파일이 있는 폴더다. 영상별 자유 HTML/SVG composition을 만들고 이 skill의 exporter로 MP4를 납품한다.

## 무엇이 움직이면 이해되는가

주제와 근거에서 시청자가 영상 끝에 답할 핵심 질문 하나를 잡는다. 이미 알려진 독자·사용처·길이는 적용하고 초안까지 만든다. 사용자가 기획 확인을 요청했거나 장면의 사실을 결정할 자료가 비어 있을 때만 먼저 묻는다.

- 기술 원리는 데이터·값·구조의 변화로, 업무 장면은 실제 입력·담당자·처리 결과로, 개념 비교는 같은 사례에서 달라지는 관계와 결과로 보여 준다. 질문에 맞는 사물과 배치를 고르고 고정 장면 유형이나 단계·노드 수에 맞추지 않는다.
- 실행 전에 시각 스토리보드에 대상, 처음과 끝의 값, 변화의 원인, 관찰할 순간을 적는다. composition의 주석과 `keyframes`로 남겨도 된다. 시간별 실행 상태는 장면 코드 한 곳에서 소유한다.
- 글자는 이름·값·단위 중심으로 둔다. 꼭 필요한 지점에만 설명 한 줄을 붙인다. 문장을 읽어야 원인과 결과를 알 수 있으면 대상의 이동·변형·대응을 다시 구성한다. 글자 등장이나 선 점멸만으로 처리를 암시하지 않는다.
- 확대·이동·전환 뒤에도 주요 대상의 ID·값·관계가 이어지게 한다. 연출 속도를 실제 처리 시간이나 성능 향상으로 제시하지 않는다. 가상 사례는 `(가상)`으로 표시한다.

기본 독자는 기술을 어느 정도 아는 사람이다. 낯선 필수 용어는 그 대상 곁에서 짧게 풀어 준다. 연출은 담백하게 하고 변화가 작거나 복잡한 곳을 확대한다.

## 화면과 시간

LinkedIn용은 10~30초, 가로:세로 **4:5**로 만든다. 다른 비율은 별도 요청이 있을 때 쓴다. 20초·1080×1350·30fps를 시작점으로 삼고 필요한 변화와 관찰 시간에 맞춰 조정한다. 길이를 채우려 장면을 늘리거나 전체를 무작정 배속하지 않는다.

레퍼런스가 없으면 어두운 중립 배경과 절제된 강조색, 읽기 쉬운 한글을 쓴다. 주요 라벨은 1080px 폭에서 30px 이상으로 시작하고 휴대폰 폭에서도 확인한다. 공간이 부족하면 내용을 덜거나 확대하며, 중요한 요소를 가장자리에서 띄운다. 결말을 잠시 유지하고 반복 재생이 인과를 역전시키지 않게 한다.

말 없이 낮은 배경음과 사건에 맞는 짧은 효과음을 사용한다. 무음에서도 의미가 이어져야 한다. 기본 exporter가 합성하는 음원은 재생성할 수 있다. 외부 음원·이미지·폰트를 쓰면 로컬 원본과 출처·사용 조건을 남긴다.

## 만들고 내보내기

한 영상의 원본은 `composition.json`과 `scene.html`이다. `assets/cache/`, `assets/order-entry/`, `assets/counterparts/`는 기술 원리·업무·비교 예제다. 현재 질문에 가까운 예제만 읽고, 모양이 맞지 않으면 새 장면을 만든다.

- JSON에는 `version: 1`, `title`, 상대 경로 `scene`, `width`, `height`, `fps`, `duration`, `representativeTime`, `keyframes: [{time, label}]`, `audio`를 둔다. 음원은 `audio.bed: {frequencies, gain}`과 `audio.events: [{time, frequency, duration, gain}]`로 조정한다. 값과 실행 조건은 예제 JSON을 참고한다.
- 별도 로컬 파일을 참조하면 선택 항목 `assets: ["상대 경로", …]`에 CSS·이미지·font·script와 그 파일들이 참조하는 필수 자산까지 등록한다. 경로 기준은 composition 폴더이며 자산을 그 안에 둔다. 등록 누락은 exporter 오류로 확인한다. 그래야 납품 원본으로 같은 화면을 재생성할 수 있다.
- HTML의 `#canvas`가 캡처할 전체 화면이다. `window.renderAt(t)`는 절대시간(초)만으로 **전체** DOM 상태를 설정하고 JSON으로 직렬화할 수 있는 의미 상태(ID·값·phase 등)를 반환한다. 순서를 바꿔 호출해도 같은 시간이면 같은 상태여야 한다. timer, 앞 프레임의 누적 상태, 원격 asset에 기대지 않는다.
- 장면은 자유롭게 작성하되 인코딩·오디오 결합·검사는 아래 공통 도구를 쓴다. 다른 skill의 script를 import하지 않는다.

```bash
python3 -m venv <스킬 폴더>/.venv
<스킬 폴더>/.venv/bin/python -m pip install -r <스킬 폴더>/requirements.txt
npm install --prefix <스킬 폴더>
<스킬 폴더>/.venv/bin/python <스킬 폴더>/scripts/render_motion.py /path/to/composition.json --check-only
<스킬 폴더>/.venv/bin/python <스킬 폴더>/scripts/render_motion.py /path/to/composition.json --output /path/to/output
```

사용자가 다른 비율을 명시한 경우에만 JSON의 크기를 바꾸고 검사·내보내기 명령에 `--allow-other-aspect`를 붙인다. 일반 제작에서는 플래그 없이 1080×1350·4:5를 유지한다.

의존성이 이미 있는 Python이면 `.venv/bin/python` 대신 그 실행 파일을 써도 된다. Python 3, Node.js, Chrome과 로컬 한글 폰트(Apple SD Gothic Neo 또는 Noto Sans CJK KR)가 필요하다. 기본 탐색이 안 되면 `NODE_BINARY`, `NODE_PATH`, `CHROME_PATH`, `MOTION_FONT_PATH`로 위치를 지정한다. ffmpeg는 `FFMPEG_PATH`·PATH·설치한 imageio-ffmpeg에서 찾는다. OS 폰트는 배포 원본에 복사하지 않고 이름과 설치 조건을 남긴다.

MP4(H.264·yuv420p·AAC), 대표 PNG, 검수 이미지, 편집 원본, 재생성 명령과 검사 기록을 남긴다. 공개 repo에는 가상 예제의 원본만 넣고 생성 영상은 납품 폴더에 둔다.

## 보고 보내기

파일 검사와 이해도 검토를 구분한다. exporter의 decode·stream·크기·길이·fps·시점·시간 순서 검사 결과를 확인한 뒤, 주요 프레임과 전환 경계에서 값·대상·관계를 직접 본다. 원본 크기와 휴대폰 폭에서 한글·라벨·잘림을 확인하고, 무음으로 전체 영상을 보고 질문에 답할 수 있는지 검토한다. 소리를 켜고 사건과의 일치·잘림·갑작스러운 시작과 끝·음량을 확인한다.

문제가 있으면 장면을 고쳐 다시 검사한다. 편집 원본으로 새 process에서 재생성해 누락된 의존성과 asset을 확인한다. 최초 시각 기준 견본은 사용자에게 보여 주고 느낌을 확인한다. 납품에는 파일 링크, 실제 길이·크기, 재생성 명령, 확인한 결과와 남은 제한을 적는다. 자동 검사를 시청자의 이해도 증명으로, 파일 생성을 LinkedIn 업로드·피드 재생 확인으로 표현하지 않는다.
