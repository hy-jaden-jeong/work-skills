# 장표 만드는 법

설명을 그림으로 보여 줄 때 읽는다. 장표는 HTML 견본을 채워 PNG로 굽는다. `<스킬 폴더>`는 이 SKILL.md가 있는 폴더다. symbolic link로 설치했다면 링크 경로를 그대로 써도 된다.

- 설명 하나에 장표 1~3장이다. 단순하면 1장, 단계가 나뉘면(재료 → 묶기 → 결과) 2~3장이다.

## 어디에 넣을 그림인가

단독으로 읽는 장표에는 아래의 제목·부제·그림·아래 글 구조를 쓴다. 문서가 이미 질문과 결론을 설명하면 그림만 넣는다. 값, 단위, 축 이름, 범례와 사물 이름은 그림에 남긴다.

본문 삽화는 견본에서 `.diagram` 요소와 그 안의 그림만 옮겨 최상위 요소를 `<div class="diagram diagram-only">`로 쓴다. `assets/slide-inline.html`이 예다. 같은 렌더 명령으로 실제로 그려진 픽셀 범위에 사방 16px 여백을 남겨 저장한다. 출력 크기는 그림마다 다르다. 작은 막대나 비교표는 그림 요소의 CSS 폭도 내용에 맞춰 잡는다. 여백을 채우려고 막대나 열을 길게 늘이지 않는다. 세로 공간이 부족하면 내용을 나누거나 단독 장표를 선택한다.

## 단독 장표 한 장

- 장표 하나에 개념 하나, 그림 하나를 담는다. 설명은 그림이 한다. 제목·아래 글을 가리고 그림만 봐도 결론을 말할 수 있어야 한다. 그림이 글 상자를 화살표로 이은 것이면 글을 읽어야 이해되고, 오른쪽 설명 패널에 몰린 글은 눈이 그림과 글을 오가게 만들었다(2026-11-18, "그림만으로 안 와닿는다").
- 모니터용 16:9 고정 캔버스(1600×900)에 다크 모드로 그리고, 3200×1800 PNG로 굽는다. 차례는 위에서 아래로 넷이다.
  - 제목(`h1`): 결론 한 문장. 장표에서 가져갈 말이 곧 제목이다.
  - 부제(`.subtitle`): 배우는 사람의 질문 · 무엇을 예로 들었는지. 지어낸 값이면 (가상).
  - 그림(`.diagram`): 폭 전체.
  - 아래 글(`.panel .key`): "그래서" 한두 문장, 공백 빼고 90자까지. 핵심·용어·읽는 법 칸은 두지 않는다. 쓰면 PNG가 안 나온다.
  - 근거(`.source`, 선택): 코드 위치·문서 한두 줄.
- 그림 규칙 셋
  - 사물은 제 모양으로 그린다. table은 실제 column과 값 3 row로(`slide-sheets`), view는 점선 표와 ƒ 값으로, "안에 들어 있다"는 겹친 상자로(`slide-nest`) 그린다. "gold.health_score (table)"라고 쓴 상자로 table을 대신하지 않는다.
  - 결론은 모양의 차이 하나로 보인다. 두 표를 꿰뚫는 칠한 column, 막힌 길(✕), 줄 그은 row, 칠한 칸 하나처럼 눈에 띄는 차이 하나에 결론을 싣는다.
  - 설명할 곳은 그림의 그 자리에 ①②③ 딱지로 짚는다(3개까지). 그림 안 글 한 덩어리는 이름·값·짧은 딱지까지이고, 코드 이름·공백 빼고 24자를 넘으면 문장으로 보고 PNG가 안 나온다.
- 처음 나오는 용어는 그 사물 바로 옆에 짧게 붙인다(예: `view` 저장된 값이 없다(수식이 걸린 엑셀 칸)). 한 장에 새 용어가 셋을 넘으면 용어 장표(`slide-glossary`)를 따로 둔다.
- 사용자에게 통한 비유는 글 한 줄로 두지 말고 그 사물 옆 딱지로 붙인다.
- 색은 "어디를 볼지"만 말한다.

  | 색 | 쓰는 곳 |
  | --- | --- |
  | 회색 | 나머지 전부 |
  | 파랑 `hl` | 지금 볼 곳 1~2곳 |
  | 빨강 `bad` | 막힘·오류 같은 진짜 문제 |
  | 주황 `alt` | 대응 장표의 두 번째 짝 |

  - 초록·노랑은 어디에도 쓰지 않는다. 성공·대기 같은 상태는 글자와 ✓·점선으로 보인다. 색마다 뜻을 붙이면(파랑=가공 중, 초록=완성…) 알록달록해지고 어디를 볼지 흐려진다.
  - 장표는 한 장에 색 두 가지, 네 곳까지이고 넘으면 PNG가 안 나온다. 순서·종류는 번호나 글로 보인다.
- 분량은 견본마다 맨 위 주석에 있다(상자 5개 안팎, 참여자 4개, 칸 6개, 막대 9줄 등). 넘치면 글자를 줄이지 말고 글을 줄이거나 장표를 나눈다.

## 표기

장표, 아래 글, 서브에이전트 지시문에 모두 적용한다.

- 문장은 한국어로 쓰고, 기술 용어는 코드·문서·UI에 나오는 영어 그대로 쓴다. 옮긴 말은 코드에서 다시 찾지 못하고, 읽는 사람이 원래 영어를 거꾸로 짐작해야 해서 오히려 어렵다.
  - 번역하지 않는다: owner(주인 ×), privilege(문 ×), service principal(로봇 계정 ×), compute(계산 자원 ×), prefix(이름표 ×), rollback(되감기 ×), row·column(줄·칸 ×), retention(보존 기간 ×)
  - 음차하지 않는다: job(잡 ×), table(테이블 ×), view(뷰 ×), task(태스크 ×)
  - 한국어로 굳은 말은 한국어로 쓴다. 도메인 용어(예: 주문, 정산, 환불)와 개발자가 평소 한국어로 말하는 것(배포, 권한, 스케줄)이 여기 든다. 헷갈리면 "팀원이 메신저에 쓰는 말"을 기준으로 고른다.
  - 비유는 괄호 안이나 "비슷한 것"에만 두고 용어를 대신하지 않는다(예: view(수식이 걸린 엑셀 칸)).
- 번역투 문장("~에 해당한다", "~를 가진다", "~에 의해 ~된다")을 쓰지 않는다. 주어와 동사가 바로 보이는 한국어로 쓴다.
- 사실은 코드·문서로 확인한 것만 쓴다. 확인 못 한 것은 "(추정)", 지어낸 값은 "(가상)"으로 표시한다.

## 모양 고르기

그리기 전에 이 장표가 답하는 질문을 한 줄로 적고, 그 질문에 맞는 모양을 고른다. 상자와 화살표(flowchart)는 "무엇이 무엇으로 이어지나"에 맞는 모양이다. "언제", "얼마나", "누가 누구에게"를 flowchart로 그리면 정작 핵심인 시간·양·순서가 그림에서 사라진다.

먼저 묶음(구조, 흐름·시간, 변화, 견줌, 용어)으로 좁히고, 그 안에서 질문이 맞는 줄을 고른다.

| 묶음 | 장표가 답하는 질문 | 모양 | 견본 (`<스킬 폴더>/assets/`) |
| --- | --- | --- | --- |
| 구조 | 무엇이 무엇으로 이어지나, 어떻게 짜여 있나 | 흐름·구조 (Mermaid flowchart) | `slide-flow.html` |
| 구조 | 어디에 사나. 이름이 비슷한데 사는 곳이 다른 것 | 묶음 (상자) | `slide-groups.html` |
| 구조 | 무엇 안에 무엇이 들어 있나 (catalog ⊃ schema ⊃ table, 폴더) | 담는 상자 (겹친 상자 + 주소) | `slide-nest.html` |
| 구조 | 이것 하나는 안이 어떻게 생겼나 (index node, list, page, packet header) | cells (칸 줄, 값으로 그림) | `slide-cells.html` |
| 구조 | 무엇 아래로 갈라지나 (B-tree, 파일 계층, 조직) | tree (값으로 그림) | `slide-tree.html` |
| 구조 | 무엇 위에서 도나 | stack (층 쌓기) | `slide-stack.html` |
| 흐름·시간 | 누가 누구에게 무엇을 요청하고 돌려받나 | 주고받기 (Mermaid sequenceDiagram) | `slide-sequence.html` |
| 흐름·시간 | 무엇이 어떤 차례로 일어나나 | 사건 순서 (Mermaid timeline) | `slide-timeline.html` |
| 흐름·시간 | 언제 시작해 얼마나 걸리나, 겹치나, 기다리나 | 시간 막대 (값으로 그림) | `slide-timebar.html` |
| 흐름·시간 | 단계마다 얼마나 남고 어디로 갈라지고 얼마나 빠지나 | 양의 흐름 (값으로 그림) | `slide-sankey.html` |
| 흐름·시간 | 어떤 event에 어느 상태로 가나 | state (Mermaid stateDiagram-v2) | `slide-state.html` |

| 견줌 | 같은 것이 두 곳에서 어떤 모양인가 | 대응 (표 + 카드) | `slide-compare.html` |

| 견줌 | 항목끼리 크기가 어떻게 다른가 (API별 응답 시간, table별 row 수) | 막대 bar (가로 막대, 값으로 그림) | `slide-bar.html` |
| 용어 | 용어 정리 | 용어 표 | `slide-glossary.html` |

- 헷갈리는 짝
  - timeline과 timebar: 차례만 중요하면 timeline, 길이·겹침·기다림이 중요하면 timebar다. timeline의 칸 간격은 실제 시간에 비례하지 않는다.
  - sequence와 flowchart: 요청과 응답이 오가는 순서가 핵심이면 sequence, 데이터가 한 방향으로 흘러 쌓이면 flowchart다.
  - sankey와 flowchart: 건수가 줄고 갈라지는 양이 핵심이면 sankey, 단계 이름과 연결만 보이면 되면 flowchart다.
  - cells와 groups: 칸 하나하나의 순서·폭이 뜻이면(node 안 key와 pointer, page 안 header와 row) cells, 서로 다른 것이 어디에 사는지면 groups다.
  - nest와 groups: 하나가 다른 것 안에 들어 있으면(포함) nest, 나란히 다른 곳에 살면 groups다. 포함을 나란한 묶음으로 그리면 "안에 있다"가 안 보인다.
  - sheets와 compare: 두 표가 column으로 이어져 무엇이 건너가고 무엇이 막히는지가 핵심이면 sheets, 같은 데이터가 두 곳에서 다른 모양이면 compare다.
  - tree와 flow: 부모 하나에 자식이 여럿으로 갈라지는 계층이면 tree, 일이 차례로 넘어가면 flow다. node 안을 칸으로 보여야 하면 tree다(flowchart는 못 그린다).
  - before-after와 compare: 같은 것의 두 시점이면 before-after, 같은 것이 두 곳(두 층, 두 system)에서 다른 모양이면 compare다.
  - state와 flow·timeline: 한 대상이 event마다 상태를 오가는 규칙(되돌아가는 화살표 포함)이면 state, 일이 넘어가는 길이면 flow, 실제로 일어난 차례면 timeline이다.
  - stack과 flow: 위 층이 아래 층을 써서 돈다(화살표 없음)면 stack, 요청이 층을 차례로 지나가는 길이면 flow다.
  - line과 timebar: 같은 값이 시점마다 얼마인지(오르내림)가 핵심이면 line, 일이 언제 시작해 얼마나 걸리는지면 timebar다.
  - line과 bar: 가로축이 시간이고 흐름이 보여야 하면 line, 서로 다른 항목의 크기를 한 시점에서 견주면 bar다. 시점 두 개뿐이면 before-after나 bar로 충분한지 먼저 본다.
  - bar와 sankey: 항목이 서로 독립이면 bar, 앞 단계의 양이 다음 단계로 갈라지고 빠지면 sankey다.
  - matrix와 compare·quadrant: 선택지 3~4개를 기준 여러 개로 ✓/✕ 하면 matrix, 두 방식을 그림으로 나란히 보이면 compare, 두 기준 위의 위치·치우침이 중요하면 quadrant다.
- 고른 모양은 서브에이전트 지시문과, 기록해 두는 곳이 있으면 거기(예: teach-me의 `deck-spec.md`)에 "모양: <모양> — <이유 한 줄>"로 적는다(예: "모양: 시간 막대 — 집계 job이 늦게 끝나 리포트 마감을 넘기는 게 핵심"). 이유가 "상자로 그리기 쉬워서"면 다시 고른다.
- 견본마다 맨 위 주석에 그 견본의 쓰는 법, 문법, 분량 기준이 있다. 견본에 없는 모양이 꼭 필요할 때만 장표 안에 `<style>`을 몇 줄 더한다.

### 견본이 없을 때

표에서 질문이 맞는 줄을 못 찾았을 때, 비슷한 견본(groups의 card, flow의 상자)으로 때우지 않는다. 읽는 사람이 구조를 못 본다.

1. 장표 2장으로 쪼개면 각 장이 표의 질문에 맞는지 본다(예: "안이 어떻게 생겼나" cells 1장 + "어떻게 찾아 내려가나" tree 1장).
2. 쪼갤 수 없으면 맡긴 쪽(메인 agent)이 `.diagram` 안에 SVG를 직접 그린다(자유 그림). 색은 `var(--hl)`·`var(--box)` 같은 slide.css 변수만, 글자는 18px 이상으로 쓴다. 자유 그림도 다른 그림과 같은 검사(글자 크기, 팔레트 밖 색, 강조 수, 넘침)를 받는다.
3. 같은 질문이 두 번 나오면 견본으로 더한다(아래 "표에 없는 모양을 더하려면"). 자유 그림은 매번 좌표를 새로 계산해야 하고 맡긴 쪽이 틀리기 쉽다.

서브에이전트는 맞지 않는 견본을 고르거나 견본을 고쳐 맞추지 않는다. "이 장표는 질문 …에 맞는 견본이 없다"고 보고하고 멈춘다. 쪼갤지, 자유 그림으로 갈지는 장표가 답할 질문을 아는 맡긴 쪽이 정해야 하고, 고친 견본은 검사를 지나도 질문에 답하지 못한다.

### 표에 없는 모양을 더하려면

Mermaid에는 이 밖에도 종류가 많다(erDiagram, quadrantChart 등). 표에 없는 종류는 기본 색이 무지개색이거나 글자가 작아서, `render_slide.py`가 "팔레트 밖 색"이나 "최소 크기보다 작다"로 PNG를 막을 수 있다. 꼭 필요하면 아래 순서로 표에 더한다.

1. 그 종류로 장표를 구워 본다. 막히면 `assets/slide.js`에 그 종류의 색·글자 크기 설정을 더한다(sequence·timeline·state 설정이 예시다).
2. 회색 바탕에 강조 1~2곳, 글자 18px 이상으로 나오면 견본(`slide-<종류>.html`)을 만들고 `--check`로 굽는다.
3. 이 표에 한 줄, `slide.js`의 `MERMAID_KINDS`에 이름을 더한다.

Mermaid `sankey-beta`, `gantt`, `quadrantChart`, `xychart-beta`, `block-beta`는 쓰지 않는다. 색을 회색으로 맞출 수 없거나 글자가 작거나 칸에서 나가는 화살표를 못 그려서 `slide-sankey`·`slide-timebar`·`slide-quadrant`·`slide-line`·`slide-bar`·`slide-cells`를 따로 만들었다.

## 만들고 굽기

1. 견본을 저장 폴더에 `NN-<개념>.html`로 복사한다. 저장 폴더와 이름 규칙은 부른 쪽이 정한다(teach-me이면 `~/onboarding/<주제>/slides/`). 정한 곳이 없으면 작업 폴더의 `slides/`에 둔다.
2. `{{…}}` 자리를 채운다. 장표 파일에는 body 안쪽만 쓴다. 스타일과 Mermaid 설정, 강조 색 정의는 굽는 순간에 들어가므로 장표에 쓰지 않는다.
3. 굽는다. 출력 경로를 생략하면 같은 이름의 `.png`가 생긴다.

   ```bash
   python3 <스킬 폴더>/scripts/render_slide.py <저장 폴더>/NN-<개념>.html
   ```

4. 종료 코드를 본다.

   | 코드 | 뜻 | 할 일 |
   | --- | --- | --- |
   | 0 | PNG를 만들었다 | PNG를 열어 확인한다 |
   | 1 | 굽지 못했다(Chrome 없음, Mermaid 문법 오류·불러오기 실패, 값 그림 문법 오류, 입력 오류). 값 그림 문법 오류는 몇 번째 줄인지 알린다 | 메시지대로 고친다. 환경 문제면 사용자에게 알린다 |
   | 2 | 장표가 규칙을 어겼다(그림 안 문장, 아래 글 90자 초과, 설명 패널(핵심·용어·읽는 법), 넘침, 그림 글자 18px 미만(보조 설명 16px 미만), 팔레트 밖 색, 강조 수, 값 그림의 줄·칸 수 상한, 빠진 구조, 채우지 않은 자리). PNG를 만들지 않고, 예전에 구운 PNG가 있으면 지운다 | 글을 줄이거나 장표를 나눠 다시 굽는다. 글자 크기를 줄여 맞추지 않는다 |

5. 기록해 두는 곳이 있으면 만든 PNG 경로를 적는다.

`python3 <스킬 폴더>/scripts/render_slide.py --check`는 견본을 구워 설치를 확인한다.

파일 쓰기 도구로 `.html`을 쓰면 미리보기 창이 저절로 열리는 앱(예: Claude 데스크톱 앱의 Browser pane)에서는 장표를 Bash(`cp` 뒤 `python3`·`sed` 치환)로 만들고 고친다.

필요한 것은 python3, Chrome(또는 Chromium·Edge), 인터넷이다. Mermaid를 CDN에서 불러오기 때문이다. Chrome이 기본 위치에 없으면 `CHROME_PATH` 환경 변수에 실행 파일 경로를 넣는다.

## Mermaid 요령

flowchart

- 상자 4개 이상을 가로(LR)로 이으면 글자가 작아져 코드 2로 막힌다. 세로(TB)로 쓴다.
- 상자 글의 줄바꿈은 `<br/>`로 한다. 강조는 `A["글"]:::hl`처럼 붙인다.
- subgraph 순서가 뒤집히면 `A ~~~ B`로 순서를 잡는다.
- 떠 있는 edge 라벨은 빼고 그 말을 상자 이름에 넣는다.
- 원형 상자에 긴 글이 넘치면 stadium `([…])`으로 바꾼다.
- subgraph 위에서 들어오는 화살표는 subgraph 제목을 지나간다. 묶음이 중심인 그림은 `slide-groups.html`로 그린다.

sequenceDiagram

- 참여자는 4개, 화살표는 8개 안팎이다. 참여자가 많거나 화살표 글이 길면 가로로 넓어져 글자가 작아진다. 화살표 글은 짧게(10자 안팎) 쓰고, 설명은 Note나 아래 글로 옮긴다.
- 강조는 구간으로 한다. 지금 볼 화살표들을 `rect hl` … `end`로 감싼다. `rect` 뒤에는 색 이름(`hl`, `alt`, `bad`)만 쓴다.
- 자기 자신에게 보내는 화살표는 글자가 세로선에 겹친다. `Note right of A: …`로 대신한다.
- HTML 주석 안에 응답 화살표(대시 둘과 `>`)를 쓰면 주석이 거기서 끝나 장표가 깨진다. 예시는 주석 밖 Mermaid 블록에만 쓴다.

timeline

- 시점에 콜론(`:`)을 쓰면 문법 오류다. `02:00` 대신 `02시`, `2시 30분`으로 쓴다.
- 칸 폭은 고정이고 줄은 공백에서만 바뀐다. 밑줄로 이은 긴 이름은 `user_activity_<br>daily_report`처럼 나눌 곳에 `<br>`을 넣는다(`<br>`은 공백으로 바뀌어 칸이 모자랄 때 그 자리에서 줄이 바뀐다). 넘치면 PNG가 안 나온다.
- 칸을 칠할 때는 시점 뒤에 `:::hl`을 붙인다(`03시 :::hl : 적재`). section을 쓰면 section 줄에 붙이고, section 전체가 칠해진다.

stateDiagram-v2

- 한 줄이 전이 하나다. 강조는 `class X hl`, 진짜 문제 상태는 `class X bad`이다. classDef는 쓰지 않는다. `slide.js`가 팔레트 색으로 붙이고, 장표에 쓴 색은 덮어쓴다.
- `class`를 붙일 상태 이름은 영문·숫자·_로 쓴다. 한글로 보이려면 `state "결제됨" as paid`로 별칭을 붙인다. 한글 이름에 바로 `class`를 붙이면 Mermaid 문법 오류다.

값으로 그림 (sankey·timebar·cells·tree·quadrant·line·bar, Mermaid 아님)

- `<pre class="sankey|timebar|cells|tree|quadrant|line|bar">` 블록에 값 줄만 쓰면 `slide.js`가 SVG로 그린다. 문법은 견본 주석에 있다.
- sankey·timebar·quadrant·line·bar는 줄 끝에 `, hl`(또는 `, alt`, `, bad`)를 붙여 칠한다. 단위는 `data-unit="건"`처럼 블록에 둔다.
- line·bar의 값에는 천 단위 쉼표를 쓰지 않는다(쉼표는 칸을 나눈다). `1200`이나 `1_200`으로 쓴다. line은 세로축이 늘 0을 품고, 값 뒤 `*`로 그 점에 값을 적고(꺾인 곳 1~2곳), `| 칸 이름, 사건`으로 세로 점선, `= 값, 이름`으로 기준 가로 점선을 긋는다. bar는 `| 값, 이름`으로 기준 세로 점선을 긋는다. 값 글자·끝 라벨·점선 이름이 겹치면 코드 2로 막는다.
- cells·tree는 칸 끝에 `:::hl`을 붙인다. 칸 하나는 "글 ; 칸 아래 설명 /폭비율 :::hl" 차례로 쓴다. 차례가 바뀌거나, `[`를 닫지 않거나, 이름·메모·층 이름에 `:::`·`/N`이 남거나, 들여쓰기가 스페이스 2칸씩이 아니면 몇 번째 줄인지 알리고 굽지 않는다. 문법 기호가 글자로 찍힌 PNG는 나오지 않는다.
- 값 그림은 `.diagram` 안에 둔다. 밖(아래 글 등)에 두면 그려지지 않으므로 코드 2로 막는다. `%%`로 시작하는 줄은 주석이다.

## 맡기기

그리기는 서브에이전트에게 맡겨도 된다. 가벼운 모델로 충분하다. 맡기는 쪽이 장표의 질문, 결론(제목), 사례 값, 눈에 보일 차이, 딱지, 아래 글을 정해 지시문에 그대로 넣는다. 서로 독립된 장표 묶음은 한 에이전트에 몰아준다. 한두 장짜리 수정·재설명 장표는 직접 만든다.

다음 장표를 미리 그려 둘 때(teach-me "장표 미리 그리기")는 background로 띄우고 완료를 기다리지 않는다. 서브에이전트가 글을 줄이거나 문구를 지을 때도 용어 규칙은 같아야 하므로, 지시문에 아래 "표기" 줄을 꼭 넣는다.

지시문 틀:

```
목표: 아래 장표 N장을 만들고 PNG로 굽는다. 제목·부제·사례 값·딱지·아래 글은 아래에 준 그대로 쓴다.
먼저 읽을 것: <스킬 폴더>/SKILL.md 의 "장표 한 장"과 "만들고 굽기"
모양: <모양> — <이 모양을 고른 이유 한 줄>
견본: <스킬 폴더>/assets/<고른 견본>
파일: <저장 폴더>/NN-<개념>.html
굽기: python3 <스킬 폴더>/scripts/render_slide.py <장표.html>
  - 코드 2가 나오면 글자를 줄이지 말고 글을 줄이거나 장표를 나눠 다시 굽고, 무엇을 바꿨는지 보고한다.
  - 준 견본이 장표의 질문에 맞지 않으면 다른 견본으로 바꾸거나 견본을 고치지 말고 그대로 보고한다.
  - 코드 0이면 PNG를 열어 겹침·잘림·잘못 붙은 edge 라벨을 확인하고, 있으면 고쳐 다시 굽는다.
표기: 문장은 한국어, 기술 용어는 영어 그대로(owner, job, view, row, column, service principal 등). 번역(주인, 줄·칸)이나 음차(잡, 테이블)로 바꾸지 않고, 글을 줄일 때도 용어는 그대로 둔다.
장표 1
- 제목: …
- 부제: …
- 질문(부제 앞): 배우는 사람이 품을 질문 한 줄
- 결론(제목): …
- 사례 값: 표면 column과 row 값 그대로, 포함이면 바깥→안 이름, Mermaid면 코드
- 눈에 보일 차이: 결론을 실을 모양 하나(칠할 column, 막힌 길, 줄 그을 row)
- 딱지: ①②③ 각각 붙일 자리와 글(공백 빼고 24자 안)
- 아래 글: "그래서" 한두 문장(공백 빼고 90자 안)
- 근거: …
보고: PNG 경로와 확인 결과 한두 줄만.
```

## 보내기 전 확인

- PNG를 직접 열어 깨진 배치뿐 아니라 틀린 사실이 있는지 본다. 장표에 넣은 사실은 코드·문서로 확인한 것이어야 한다.
- 용어 표기를 본다. 기술 용어를 한국어로 옮겼거나(owner→주인, row→줄) 음차했으면(job→잡) 영어로 되돌린다. "~에 해당한다", "~를 가진다" 같은 번역투 문장도 고친다. 기준은 위 "표기"다.
- 모양을 본다. 그림이 장표의 질문(언제, 얼마나, 누가 누구에게)에 바로 답하는지 확인한다. 시간·양·주고받기를 상자와 화살표로 그렸으면 "모양 고르기" 표대로 다시 그린다.
- 가리고 본다. 제목과 아래 글을 가리고 그림만 봤을 때 결론을 말할 수 있는지 확인한다. 말하려면 글을 읽어야 하면 사물을 제 모양으로 다시 그린다.
- 줄여 본다. 채팅 창에서는 PNG가 폭 760px 안팎으로 보인다. 그 크기로 줄여도 딱지와 값이 읽히는지 본다(macOS는 `sips -Z 760 <장표.png> --out <작은.png>`).
- 고칠 것이 있으면 고쳐 다시 구운 뒤 사용자에게 보여 준다. 이미지를 보낼 수 있는 도구면 PNG를 보내고, 아니면 PNG 경로를 알려 준다.
- 장표를 보낸 뒤에는 장표 순서대로, 장표마다 핵심 한 줄을 먼저 쓰고 설명한다. 채팅 설명은 장표를 보충할 뿐 그림을 대신하지 않는다.
- 구조를 보여 줄 때 답변 본문에 ASCII 그림(코드 블록 안의 트리·화살표)을 쓰지 않는다. 짧은 답이라도 장표로 굽는다.
