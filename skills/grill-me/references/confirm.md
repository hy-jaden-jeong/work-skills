# 확정 (spec으로 남길 때)

인터뷰에서 정한 것을 사용자가 뜻대로 이해했는지 확인하고 확정을 받는다.

1. spec에 동작 표와 test할 seam을 채운다. 결정 표에서 동작을 끌어낸다. 형식은 같은 폴더의 `spec-format.md`를 따른다.
   - 이미 돌아가는 것을 바꾸는 일이면 "기존 <무엇>이 그대로 나온다"를 대상과 함께 동작으로 적는다(예: "기존 장표 전부가 바꾸기 전과 같은 PNG로 구워진다"). 무엇이 그대로여야 하는지는 범위라 사용자와 정한다. 증명하는 법은 build-to-spec이 정한다.
2. 설계 전체를 한 번 가르친다. 그림을 먼저 보여 주고, 한 문단으로 결과와 이유를 설명하고, 결정 목록으로 끝낸다. SKILL.md의 "가르치는 법"을 따른다.
3. 되돌리기 비싼 결정(SKILL.md의 "사실과 결정")마다 장면 하나로 결과를 확인한다. 누가 정했든 되돌리기 비싸면 확인한다. "이 결정이면 <장면>에서 <결과>가 됩니다. 원하는 결과가 맞나요?" 사용자가 뜻을 다르게 알고 동의한 결정을 여기서 잡는다.
4. 결정 목록을 번호(D1, D2, …)와 함께 보여 준다. 사용자가 답한 것, agent가 정한 것, 추천대로 정한 것을 구분한다.
5. test할 seam이 드러나는 사례를 설명한 뒤 “이대로 확정 / 일부 수정 / 설명 더 듣기”를 객관식으로 묻고 답을 기다린다.
6. 사용자가 일부를 고치면 그 결정과 거기에 달린 결정만 다시 묻는다.

통과: 사용자가 확정을 선택하거나 직접 확정 의사를 밝혔다. spec의 상태를 "확정"과 날짜로 바꾼다. 그다음은 SKILL.md의 "그다음"을 따른다.

파일 없이 인터뷰를 끝낸 뒤 spec으로 옮길 때도 이 파일을 따른다. 대화의 결정 목록을 결정 표에 옮기고, 문제·목표·하지 않을 것·제약을 채운 뒤 1번부터 한다.
