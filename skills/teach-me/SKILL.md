# teach me

요청자가 무엇을 이해하고 무엇을 할 수 있게 되려는지에 맞춰 가르친다. 기본 흐름은 **맥락 확인 → 객관식 진단 → 완결된 전체 설명 → 개념 하나씩 확대 → 객관식 퀴즈 → 실제 답 이후 채점·재설명**이다. 설명한 것과 이해를 확인한 것을 구분한다.

사용자가 "전체 설명부터", "퀴즈 없이", "이 부분부터"를 원하면 그 순서와 범위를 따른다. 이미 답한 질문과 확인된 개념을 반복하지 않는다. 짧은 교육 요청에는 흐름을 작게 적용하고, 고정된 장 수나 모든 퀴즈 통과를 완료 조건으로 삼지 않는다.

## 선택 화면과 답 기다리기

- 현재 노출된 도구의 schema와 실행 모드부터 확인한다. 선택 화면이 있으면 쓰고, 없거나 중립적인 문항을 표현할 수 없으면 같은 보기를 번호 목록으로 보여 주고 채팅 답을 기다린다.
- Claude Code의 `AskUserQuestion`, Codex의 `request_user_input_async` 등 사용 가능한 선택 도구를 쓴다. Codex의 `request_user_input_async`가 단일 선택 `options: string[]`이면 보기 문자열을 보내고 **개념별로 질문을 나눈다**. 여러 개 고르기나 다른 도구의 option object를 가정하지 않는다.
- `request_user_input`은 Plan 모드 한정이거나 보기 2~3개·추천 표시가 필수일 수 있다. 현재 모드에서 허용될 때만 쓰고, 추천 표시가 답을 암시하는 진단·퀴즈에는 중립적인 다른 도구나 번호 목록을 쓴다. 도구를 쓰려고 실행 모드를 바꾸지 않는다.
- 비동기 입력의 대기·턴 종료는 상위 실행 환경 지침을 따른다. 입력이 아직 대기 중이면 그 환경이 허용하는 방식으로 기다린다. 도구가 답 없이 완료된 경우에만 환경의 fallback 지침을 적용한다. 대기를 지원하지 않으면 문항을 채팅에 남겨 다음 답에서 잇는다.
- 무응답, 시간 경과, 미리 선택된 보기, "다음"은 정답이 아니다. 답을 추측하거나 대신 만들지 않는다. 답이 아직 없으면 채점하지 않고 미확인으로 남긴다. 이미 선택 화면에 답했다면 같은 답을 채팅으로 다시 요구하지 않는다.

## 맥락과 학습 상태

먼저 대화와 사용자가 제공한 자료, 기존 `~/onboarding/<주제>/` 기록을 확인한다. 폴더가 있으면 아래 세 파일을 읽고 멈춘 지점부터 잇는다. 목표나 이해 범위가 이미 드러났으면 다시 묻지 않는다.

- `deck-spec.md`: 학습 목적·원하는 깊이, 전체 설명 요약, 유동적인 목차, 단계 상태(남음 / 설명함 / 확인됨 / 건너뜀·미확인), 단계별 해설·근거·장표 PNG 경로. 설명함은 이해 확인과 다르다.
- `glossary.md`: 정의한 용어(묶음 / 용어 / 한 줄 뜻 / 비슷한 것). 용어가 쌓이면 한 장 정리의 원본으로 쓴다.
- `learning-record.md`: 주제별 **알고 있다고 말함 / 확인됨 / 건너뜀·미확인**을 나눠 기록한다. 자기평가 답, 실제 문항과 선택·결과·근거, 틀린 개념, 도움이 된 설명 방식, 다음에 확인할 것을 남긴다. 정답 하나로 주제 전체를 숙달했다고 기록하지 않는다.
- `research/`: 자료 조사 보고서와 근거. `slides/`: 장표 HTML과 PNG.

새 학습은 이 폴더에 필요한 기록을 간결하게 만든다. 짧은 학습은 목차와 기록도 작게 둔다. 사용자가 채팅만 원하거나 파일을 쓸 수 없으면 같은 상태를 대화에 요약해 재개할 수 있게 한다. 진도를 물으면 설명한 범위와 확인된 범위가 드러나는 목차 표를 보여 준다.

## 시작: 목적과 현재 이해 진단

1. 주제와 기존 맥락을 확인한다. 자료가 필요하면 읽고, 주제가 모호하면 지금 맥락에서 가능한 주제·범위를 선택지로 좁힌다. subagent가 있고 현재 지침이 위임을 허용하면 자료 조사를 작업 모델에게 맡길 수 있다. 없으면 직접 조사한다. 조사를 기다리는 동안 목적·이해 범위를 물을 수 있다.
2. 목적이 드러나지 않았으면 실제로 하고 싶은 행동을 객관식으로 묻는다. 예: "용어와 흐름을 설명하고 싶다 / 예시를 직접 풀고 싶다 / 실제 상황에서 판단하고 싶다". 주제에 맞춰 보기를 쓰고 답에 따라 설명의 깊이와 사례를 고른다.
3. 현재 이해를 **주제별 개념이나 가능한 행동**으로 묻는다. "초보 / 중급 / 고급"만 묻지 않는다. 예: "API 요청과 응답을 구분할 수 있나요? — 예시에서 둘을 짚을 수 있다 / 이름은 알지만 예시에서는 헷갈린다 / 둘 다 처음 듣는다". 아직 가르치지 않은 용어에는 짧은 뜻이나 예시를 붙인다. 필요한 기초부터 적은 수의 질문으로 시작하고, 중요하게 남은 차이는 학습 중 확인한다.
4. 자기평가는 "알고 있다고 말함"으로 기록한다. 출발점을 정하는 데 필요하면 부담이 작은 예시 문항 하나로 확인한다. 진단을 장시간 지식 시험으로 만들지 않는다. 이전 답이나 기록으로 확인된 이해는 재검사하지 않는다.
5. 답을 근거로 익숙한 부분은 압축하고 필요한 기초와 핵심을 남긴다. 무응답이면 이해를 단정하지 않는다. 대기 중인 질문은 위 대기 규칙을 따르고, 답 없이 완료된 도구에 대해 환경이 계속 진행하도록 지시하면 미확인 상태로 쉬운 전체 설명부터 진행한다.

## 전체 설명: 한 차례 끝까지

진단 뒤에는 **문제·목적 → 핵심 요소의 관계 → 구체 사례의 시작부터 결과까지**를 한 차례 완결되게 설명한다. 목차만 보여 주고 곧장 1장으로 뛰지 않는다.

- 큰 그림을 먼저 보여 주고, 각 요소가 왜 필요한지와 서로 무엇을 주고받는지 글로 풀어 준다. 한 사례를 처음 조건·입력부터 처리·변화와 최종 결과까지 따라간다. 일반 개념은 그 개념을 쓰기 전 상황, 적용 과정, 달라진 결과를 보여 준다.
- 요청자의 이해에 맞춰 분량을 조절한다. 아는 요소는 연결만 짚고, 낯선 요소는 그 사례에서 정의한다. 전체 설명 중간마다 퀴즈로 끊지 않는다. 세부를 모두 다루려다 큰 그림이 사라지지 않게 한다.
- 끝에는 핵심 관계와 이제 확대할 개념의 위치를 짚고 짧은 학습 순서를 제시한다. 필요한 단계 수는 주제와 목적에 맞춰 정하며, 진단이나 퀴즈 결과가 바뀌면 순서도 바꾼다.
- 정상 흐름을 먼저 설명한다. 실패·장애는 사용자가 묻거나 학습 목적·개념 자체에 필요할 때 다룬다. 자료의 이슈 절을 설명의 뼈대로 삼지 않는다.

## 세부 설명: 큰 그림 안에서 하나씩

- 매 단계에서 "전체 흐름의 어디를 확대하는지" 한 문장으로 연결한다. 한 번에 개념 하나를 중심으로 **그림 → 구체 예시 → 무엇이 왜 변하는지**를 설명한다. 용어 이름만 나열하지 않는다.
- 한 개념에 필요한 만큼만 장표를 쓴다. 여러 변화가 한 장에서 안 보이면 앞 장에 하나씩 더한다. 새 용어가 많으면 나눠 설명하거나 용어 장표를 따로 둔다.
- 아는 개념에는 대응시켜 설명한다. 서로 다른 사물은 같은 사례의 실제 모양·값으로 비교하고, 대응하는 부분은 같은 색으로 그린다. 비유는 보조로 쓰며 실제 용어를 대신하지 않는다.
- 그림과 글을 모두 본 뒤 풀 수 있는 객관식 퀴즈를 바로 낸다. 매번 "퀴즈를 낼까요?"를 묻지 않는다. 사용자가 퀴즈를 원하지 않으면 설명만 진행하고 이해는 미확인으로 남긴다.

## 그림·용어·근거

- PNG 장표는 나란히 설치된 `draw-diagram`의 `<skills 폴더>/draw-diagram/SKILL.md`를 읽고 그 지침으로 그린다. `<skills 폴더>`는 이 skill 폴더의 위 폴더다. 굽기는 `python3 <skills 폴더>/draw-diagram/scripts/render_slide.py <장표.html>`이다. 첫 장표 전에 `--check`로 환경을 확인한다.
- `draw-diagram`이 없거나 렌더링이 안 되면 가능한 범위에서 원인을 해결하되 학습을 막지 않는다. 사용할 수 있는 Mermaid·간단한 텍스트 그림 등으로 관계를 보여 주고 계속한다. 기능이 없는 환경에서 PNG가 만들어졌다고 주장하지 않는다.
- 장표는 `~/onboarding/<주제>/slides/NN-<개념>.html`과 PNG로 둔다. 전체 설명은 `00-overview`, 세부 확대는 `-detail`, 재설명은 `-redo-<각도>`처럼 구분한다. PNG를 열어 사실·용어·가독성을 확인하고 채팅에 표시한 뒤 글로 해설한다.
- 모양은 그림이 답할 질문에 따라 고른다. 차례는 timeline, 주고받기는 sequence, 걸린 시간은 timebar처럼 내용에 맞춘다. table은 값이 든 표, 포함 관계는 겹친 상자로 그린다. 상세 모양·견본은 `draw-diagram`에 두며 여기서 복제하지 않는다. 그림만 보고도 핵심 관계와 변화가 보여야 한다.
- 처음 나오는 용어는 예시와 그림의 해당 사물 옆에서 짧게 정의한다. 문장은 한국어로, 기술 용어는 코드·문서·UI에 나온 영어 그대로 쓴다(job, table, view, schema 등). 도메인과 일상에서 한국어로 굳은 말(주문, 정산, 배포 등)은 한국어로 쓴다. 같은 것은 끝까지 같은 이름으로 부른다. 번역투 문장은 피한다.
- 특정 문서·레포·시스템의 사실은 실제 자료로 확인하고 `path:line`이나 문서 위치를 남긴다. 일반 개념·도메인은 사용자 제공 자료나 필요한 공개 근거를 이용하고, 사실 확인이 필요하면 신뢰할 수 있는 자료를 조회해 출처 링크를 붙인다. 확인하지 못한 부분은 "(추정)", 지어낸 사례·값은 "(가상)"으로 표시한다.

### 다음 장표 준비 (가능할 때)

사용자가 현재 그림을 읽거나 답하는 동안 한 단계 앞 장표를 준비할 수 있다. subagent와 background 실행을 쓸 수 있고 위임이 허용될 때만 싼 모델에게 맡기며, 없으면 필요할 때 직접 그린다.

- `deck-spec.md`의 해설·근거, `research/` 경로, `learning-record.md`의 이미 아는 것·오답을 전달한다. 현재 개념의 세부 장표와 바로 다음 개념까지만 준비한다. 재설명은 실제 오답을 본 뒤 만든다.
- 목차의 장표 상태는 없음 / 그리는 중 / 준비됨 / 보냄과 PNG 경로로 남긴다. 재개할 때 준비된 장표를 다시 그리지 않는다.
- 보내기 전에 PNG를 열어 근거와 대조한다. 새 답 때문에 설명의 깊이·각도가 달라졌으면 준비한 장표도 고친다. 장표를 기다릴 때는 무엇을 그리는지 한 줄로 알린다.

## 퀴즈와 답 이후 적응

1. 방금 가르친 핵심으로 상황 적용·차이 구분·원인 추론을 묻는다. 다루지 않은 곁가지나 숫자 암기를 시험하지 않는다. 필요하면 해당 부분을 확대한 그림과 해설을 먼저 보여 준다.
2. 기본은 문항 하나씩, 그럴듯한 답 보기와 "모르겠다 / 아직 헷갈린다"를 함께 낸다. 보기는 보통 답 후보 3개와 모르겠다이며, 수는 실제 도구 제약에 맞춘다. 정답 위치를 섞고 보기 길이를 비슷하게 맞춘다. 추천 표시나 보기 설명에 정답 힌트를 붙이지 않는다.
3. **실제 답을 받은 뒤** 고른 답·결과·이유를 짧게 알려 준다. 여러 문항이면 표로 정리한다. 맞힌 답도 왜 맞는지와 헷갈릴 오답 하나의 차이를 짚되, 익숙한 부분을 매번 길게 되풀이하지 않는다. 찍은 답인지 구분할 필요가 있으면 다른 상황에 적용하는 한 문항이나 짧은 이유를 요청한다.
4. 오답이나 모르겠다는 같은 문장을 반복하지 말고 **다른 예시·관점의 그림과 원인 설명**으로 다시 가르친다. 시간 순서, 값의 변화, 익숙한 비유, 반례 중 오해를 풀 방식을 고른다. 재확인은 숫자만 바꾸기보다 같은 핵심을 다른 상황에 적용하게 한다.
5. 답의 근거에 맞춰 난도와 다음 단계를 정한다. 핵심 관계가 확인되면 다음 개념이나 더 깊은 적용으로, 오해가 있으면 필요한 기초로 돌아간다. 이전에 헷갈린 개념은 관련 있는 뒤 문항에서 다시 확인한다. "다음" 요청이면 이동하되 답하지 않은 문항은 건너뜀·미확인으로 기록한다.
6. 같은 개념에서 반복해 막히면 설명 방식과 필요한 기초를 바꾼다. 두 차례 재설명 뒤에도 어렵다면 "기초부터 다시 / 다른 예시로 더 보기 / 일단 넘어가기"를 선택지로 제시한다. 사용자가 택한 경로를 따르고 반복 통과를 강제하지 않는다.
7. 확인된 범위·남은 오해와 다음 지점을 기록한다. 매 단계 이동마다 허가를 묻지 않고 답에 맞춰 이어 가되, 사용자가 멈추거나 다른 부분을 원하면 따른다.

답 대신 질문이나 "다시 설명해줘"가 오면 그것부터 처리한다. 곁가지는 필요한 예시·설명으로 답하고 큰 그림의 원래 위치로 돌아온다. 관계나 변화가 잘 안 보일 때 그림을 보태며, 짧은 확인에 매번 새 PNG를 만들지 않는다. 설명의 오류를 발견하면 인정하고 근거를 확인해 글·그림·기록을 고친다. 이미 처리한 같은 응답을 중복 채점하지 않는다.

## 마무리와 재개

학습 목적에 필요한 범위를 다뤘거나 사용자가 멈추면 확인된 이해, 알고 있다고 말한 부분, 건너뜀·미확인, 다시 볼 그림·근거와 다음 출발점을 짧게 정리한다. 원하거나 이해 확인에 도움이 될 때만 핵심과 이전 오해를 섞은 종합 퀴즈를 낸다. 퀴즈를 생략했다면 설명을 마친 범위만 보고하고 숙달로 기록하지 않는다.

"다음 장"은 기록의 다음 지점에서, "퀴즈 내줘"는 설명한 개념에서 잇는다. 기록이 없으면 필요한 맥락만 확인하며, 재개 요청을 이전 문항의 정답이나 전체 이해 확인으로 간주하지 않는다.
